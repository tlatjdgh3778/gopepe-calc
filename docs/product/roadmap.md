# 로드맵: gopepe-calc (포지션 계산기)

- 최종 갱신: 2026-11-25

## v1 (MVP)

개발 순서: F-0 → F-1 → F-7 → F-2 → F-3 → F-4 → F-5 → F-6 (F-2·F-4·F-5는 서로 독립이라 순서 교환 가능)

| ID | 기능 | 요청 한 줄 | 의존 | 상태 |
|---|---|---|---|---|
| F-0 | 프로젝트 골격 | 앱이 빌드되고, 빈 단위 테스트 1개와 빈 E2E 1개가 실제로 통과하며, 빌드·테스트·E2E·개발 서버 명령이 CLAUDE.md에 기록된다 | - | 완료 |
| F-1 | 손익 계산 | 사용자가 심볼(BTC/ETH/SOL)·방향·레버리지를 고르고 진입가·종료가·수량을 넣으면 필요 증거금·손익·ROE가 바로 표시된다 | F-0 | 완료 |
| F-7 | 입력 검증·단위 반올림 | 레버리지가 심볼 최대치를 넘거나 수량이 최소 단위보다 작으면 경고하고, 결과를 심볼의 틱·수량 단위에 맞춰 반올림하며, 심볼 정보 기준일을 표시한다. (→ F-7(`docs/specs/input-validation.md`): 실제 단위 내림은 USDT 환산 수량(DoD-14·DoD-15)뿐이고 결과 표시 규칙은 F-1 그대로다(비목표). 틱 반올림·가격 표시 헬퍼(`roundToStep`·`formatPrice`)는 F-2·F-3이 쓴다.) 함께 F-2·F-3·F-4·F-5를 병렬로 개발할 공통 기반(확장 심볼 데이터, 가격 반올림·표시 헬퍼, 탭 화면, 공용 입력 컴포넌트, F-1 E2E 범위 좁히기, 포트 환경변수, worktree 위치)을 만든다 | F-1 | 완료 |
| F-2 | 목표가 | 사용자가 진입가와 목표 수익률(%)을 넣으면 그 수익률이 나오는 가격이 표시된다 | F-1 | 완료 |
| F-3 | 청산가 | 사용자가 격리/교차를 고르고 진입가·수량(교차면 계좌 잔고)과, 원하면 손절가를 넣으면 추정 청산가와 진입가 대비 거리(%)가 표시된다. 손절가가 청산가보다 불리하면 "손절 전에 청산됨"을 경고하고, 유지증거금률 첫 단계 한도를 넘으면 경고하며, 추정치라는 고지를 함께 띄운다 | F-1 | 완료 |
| F-4 | 최대 진입 수량 | 사용자가 진입가와 사용 가능 잔고를 넣으면 최대 수량과 포지션 가치가 표시된다 | F-1 | 완료 |
| F-5 | 평균 진입가 | 사용자가 진입 행(가격, 수량)을 추가·삭제하면 평균 진입가와 총 수량이 바로 갱신되고, 입력 중 포커스가 유지된다 | F-1 | 완료 |
| F-6 | 피라미딩 터미널 | 앱 화면을 탭형 계산기에서 거래 터미널형 피라미딩 화면 하나로 전면 교체한다(참고: `docs/product/references/pyramid-terminal-wireframe.html`의 "거래 터미널" 시안). 사용자가 심볼(유지증거금률·최대 레버리지 자동 적용)·방향·최초 진입가·초기 증거금·레버리지(슬라이더, 상한은 심볼 `maxLeverage`)·수수료율과 추가 진입 단계(가격, 수익 재투입 %)를 넣으면 포지션 요약(평단·추정 청산가·실효 레버리지·총 수량·총 자산·본전가·누적 수수료), 단계별 경로(차트·표), 익절(익절가 ↔ 목표 ROE 연동, 순수익, 단일 진입 대비 비교), 손절(손절 손익, 손익비, 청산가까지 거리, 손절 전 청산 경고)이 바로 표시된다. 손익·청산가·본전가는 진입·종료 수수료를 반영하고, 재투입한 미실현 수익은 청산가 담보에 더하지 않으며, 재투입할 수익이 없거나 직전 진입가보다 수익 방향이 아닌 단계는 무시하고 경고한다. 시나리오 저장은 하지 않는다(F-12) | F-3, F-4, F-5 | 대기 |

출처: v1 기능 구성·요청 한 줄·개발 순서 [제안 후 승인] / F-6의 v1 편입, F-3의 손절가 입력, F-7의 공통 기반(`docs/specs/input-validation.md` 1장) [사용자 결정] / F-6을 거래 터미널형 피라미딩 화면으로 전면 교체, 수수료 포함, 시나리오 저장 제외, 심볼 선택 + 유지증거금률 자동 적용, 레버리지 상한 = 심볼 `maxLeverage` (2026-11-25) [사용자 결정]

## 제외
- 실제 주문 실행·거래소 계정 연동 — 사유: 시뮬레이션 전용 도구다. [제안 후 승인]
- 화면에서 실시간 가격·거래소 API 호출 — 사유: 외부 API 장애·지역 차단과 무관하게 항상 동작하게 한다. [제안 후 승인]
- 입문자용 용어 설명·교육 콘텐츠 — 사유: 대상 사용자가 거래소 계산기 경험자다. [제안 후 승인]
- 코인 마진(인버스) 선물, 헤지 모드 — 사유: 하지 않기로 결정(손익 계산 방식·포지션 모델이 달라 범위가 커진다). [사용자 결정]
- 회원가입·로그인·서버 저장 — 사유: 백엔드 없는 계산 도구로 유지한다. [제안 후 승인]
- 개별 계산기 탭 화면(손익·목표가·청산가·최대 수량·평균 진입가) — 사유: F-6에서 피라미딩 화면 하나로 전면 교체한다. F-1~F-5의 계산 모듈(`lib/`)은 F-6이 재사용한다. [사용자 결정]
