구조 원칙:
- 계산 로직은 화면과 완전히 분리된 순수 TS 모듈로 둔다. 화면 없이 계산만 단위 테스트로 검증한다.
- 같은 입력으로 Bybit 계산기와 결과가 일치하는지 테스트로 고정한다. 수수료를 반영한 청산가·본전가처럼 Bybit 계산기에 대응 값이 없는 F-6 결과는 공식을 손으로 계산한 리터럴로 고정한다. [사용자 결정]
- F-6은 F-1~F-5의 계산 모듈(`lib/`)을 재사용한다. 예: 수수료 반영 청산가는 `liquidationPrice`에 담보 = 원금 − 누적 진입 수수료, `mmr` = 유지증거금률 + 수수료율을 넘긴다.

## 검토했지만 고르지 않은 선택지
- Tailwind·shadcn 없이 가벼운 구성 — 입력 폼·탭·경고 같은 UI 요소를 직접 만들어야 한다.
- 화면에서 Bybit 공개 API 실시간 호출 — API 장애·지역 차단에 의존하게 된다. 심볼 확대가 필요하면 개발용 스크립트로 받아 파일로 저장한다(F-10).

## 후속 확인
- F-6 스펙에서 정한다: 경로 차트 구현 방식(SVG 직접 작성 vs shadcn chart(Recharts)), 폰트(시안의 DM Sans·Noto Sans KR, 숫자 고정폭) 채택 여부, 수수료율 기본값, 추가 수량을 `qtyStep`으로 내릴지 여부.
- F-0에서 Playwright 브라우저 설치 방법(`bunx playwright install chromium`)과 E2E 실행 방법을 CLAUDE.md에 적는다.
- F-7에서 BTC/ETH/SOL의 유지증거금률 첫 단계·최대 레버리지·단위 값을 Bybit 공개 API로 조회하고 화면과 대조해 기준일과 함께 기록한다(유지증거금률 첫 단계도 F-7이 기록하고, 전체 단계는 F-10에서 한다). [사용자 결정]
