# 기술 스택: gopepe-calc (포지션 계산기)

- 최종 갱신: 2026-11-19

| 항목 | 결정 | 이유 | 출처 |
|---|---|---|---|
| 플랫폼 | 웹 | 열어서 바로 쓰는 계산 도구이고, gopepe 웹 프로젝트에 통합할 예정이다 | [제안 후 승인] |
| 언어·프레임워크 | TypeScript · Next.js 16 · React 19 · bun, UI는 Tailwind 4 + shadcn(base-ui) | 이후 gopepe-swap 등과 하나의 프로젝트로 합칠 때 수월하도록 같은 스택을 쓴다 | [사용자 결정] |
| 백엔드 | 없음 — 모든 계산은 브라우저에서 수행 | 실시간 API·서버 저장을 하지 않는다 | [제안 후 승인] |
| 데이터 저장 | 없음 — 심볼 정보(BTC/ETH/SOL의 유지증거금률 첫 단계·최대 레버리지·틱·수량 단위·최소 수량)만 레포 안 파일에 기준일과 함께 기록 | 심볼 정보는 거의 바뀌지 않아 실시간으로 받을 이유가 없다 | [제안 후 승인] |
| 인증 | 없음 | 회원가입·로그인 제외 | [제안 후 승인] |
| 외부 서비스 | 없음 | 주문·거래소 연동·API 호출 제외 | [제안 후 승인] |
| 단위 테스트 도구 | Vitest (+ Testing Library, jsdom). 정적 검사는 oxlint · oxfmt · tsc | gopepe-swap과 같은 도구 | [제안 후 승인] |
| E2E 도구 | Playwright (Chromium) | gopepe-swap과 같은 도구. 외부 의존이 없어 앱만 띄워 실행한다 | [제안 후 승인] |

구조 원칙:
- 계산 로직은 화면과 완전히 분리된 순수 TS 모듈로 둔다. 통합할 때 이 모듈만 공용 패키지로 옮긴다.
- 같은 입력으로 Bybit 계산기와 결과가 일치하는지 테스트로 고정한다.

## 검토했지만 고르지 않은 선택지
- Tailwind·shadcn 없이 가벼운 구성 — gopepe-swap과 UI 스택이 달라져 통합 시 다시 맞춰야 한다.
- 화면에서 Bybit 공개 API 실시간 호출 — API 장애·지역 차단에 의존하게 된다. 심볼 확대가 필요하면 개발용 스크립트로 받아 파일로 저장한다(F-10).

## 후속 확인
- F-0에서 Playwright 브라우저 설치 방법(`bunx playwright install chromium`)과 E2E 실행 방법을 CLAUDE.md에 적는다.
- F-1·F-3에서 BTC/ETH/SOL의 유지증거금률 첫 단계·최대 레버리지·단위 값을 Bybit 화면에서 확인해 기준일과 함께 기록한다.
