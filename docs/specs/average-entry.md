# 스펙: F-5 평균 진입가

- 상태: 완료
- 최종 갱신: 2026-11-25

## 1. 목표
사용자가 `/` 화면의 "평균 진입가" 탭에서 심볼(BTCUSDT·ETHUSDT·SOLUSDT)을 고르고 진입 행(진입가, 수량)을 추가·삭제·입력하면, 평균 진입가(Σ(진입가×수량) ÷ Σ수량)와 총 수량이 계산 버튼 없이 바로 갱신되고, 행을 추가·삭제하거나 입력하는 동안 포커스가 유지된다. 계산 함수는 숫자 배열을 받는 순수 함수로 두어 F-6(불타기 시나리오)이 다시 쓸 수 있게 한다. [사용자 결정]

## 2. 비목표
- 방향·레버리지를 입력받지 않고, 필요 증거금·손익·청산가를 계산하지 않는다(청산가는 F-3, 단계별 계산은 F-6). [사용자 결정]
- 총 포지션 가치(USDT)를 표시하지 않는다. [사용자 결정]
- 평균 진입가를 심볼 틱 단위로 반올림하지 않는다. [사용자 결정]
- 수량은 기초 코인 단위로만 받고 USDT 단위 입력 토글을 두지 않는다. [제안 후 승인]
- 수수료 반영(F-8), 행 순서 바꾸기·끌어 옮기기, 입력 저장·URL 반영을 하지 않는다. [제안 후 승인]
- 공용 모듈(`lib/input.ts`, `lib/format.ts`, `lib/symbols.ts`, `lib/validation.ts`, `components/fields/`의 기존 파일, `components/calculator-layout.tsx`, `components/calculator-tabs.tsx`)과 `CLAUDE.md`의 공용 모듈 목록을 수정하지 않는다. 수량 경고 문구는 F-5 안에 복제한다. [제안 후 승인]
- 결과가 부동소수점 범위를 넘는 극단 입력(대략 1e300 이상)에서 결과의 정확성은 보장하지 않는다. 이런 입력에서 보장하는 것은 §5 머리의 공통 불변식뿐이다. [제안 후 승인]

## 4. 인터페이스 계약
- `lib/average-entry.ts`: `averageEntry(entries: { price: number; qty: number }[]): { avgPrice: number; totalQty: number } | null`. 반올림하지 않은 원값을 돌려준다. 배열이 비었거나, `price`·`qty` 중 0 이하이거나 유한하지 않은 값이 하나라도 있거나, 결과가 유한하지 않으면 `null`이다. [사용자 결정]
- `components/average-entry-calculator.tsx`: `AverageEntryCalculator`(props 없음). [제안 후 승인]
- `app/page.tsx` 탭 항목: `value` `"average-entry"`, `label` `"평균 진입가"`, `content`는 `AverageEntryCalculator` 요소이고 줄 끝에 꼬리표 `// F-5`를 둔다. [제안 후 승인]
- 함수 이름·파일 위치는 구현 단계에서 바꿀 수 있다. 고정하는 계약은 입출력의 의미와 `null` 규칙, 입력·결과 접근 이름, 탭 항목의 `label`이다. [제안 후 승인]
- URL은 `/`만 쓴다. 새 라우트·API는 없다. [제안 후 승인]

## 5. 엣지 케이스와 실패 시나리오
화면에는 어떤 입력에서도 `NaN`·`Infinity`·콘솔 오류가 나타나지 않는다. [제안 후 승인]

### 5.1 비정상 입력
- EC-1: 진입가·수량 입력란은 숫자와 소수점 하나만 받는다. 다른 문자나 두 번째 소수점이 섞인 변경(붙여넣기 포함)은 통째로 무시되고 직전 값이 유지된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-2: 입력란 원문이 `""`이거나 `.`이면 그 칸은 빈 칸으로 본다 — 검증: 컴포넌트 테스트 [제안 후 승인]

### 5.2 행 상태
- EC-3: 진입가·수량이 모두 빈 칸인 행은 계산에서 빠지고, 나머지 행으로 결과가 표시된다 — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-4: 진입가·수량 중 한 칸만 빈 칸인 행이 하나라도 있으면 두 결과는 `—`다 — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-5: 진입가나 수량이 0인 행이 하나라도 있으면 두 결과는 `—`다 — 검증: 단위 테스트(`null` 반환) + 컴포넌트 테스트 [사용자 결정]
- EC-6: 모든 행이 빈 행이면 두 결과는 `—`다 — 검증: 단위 테스트(빈 배열 `null` 반환) + 컴포넌트 테스트 [사용자 결정]
- EC-7: 입력을 지워 EC-4~EC-6에 해당하게 되면 두 결과가 `—`로 돌아간다 — 검증: 컴포넌트 테스트 [제안 후 승인]

### 5.3 수량 경고
- EC-8: 행의 수량이 심볼 `minOrderQty`보다 작으면 그 수량 입력란 아래에 `⚠ 최소 주문 수량은 {formatCoinQty(minOrderQty, qtyStep)} {코인}입니다.`가 표시되고 입력란과 `aria-describedby`로 연결된다 — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-9: 행의 수량이 `qtyStep`의 배수가 아니면 그 수량 입력란 아래에 `⚠ 수량 단위는 {formatCoinQty(qtyStep, qtyStep)} {코인}입니다.`가 표시되고 입력란과 `aria-describedby`로 연결된다 — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-10: EC-8과 EC-9에 함께 해당하면 EC-8의 경고 하나만 표시한다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-11: 수량 원문이 비었거나 `.`이거나 0이면 수량 경고를 판정하지 않는다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-12: 수량 경고가 표시되어도 두 결과는 계속 계산·표시된다 — 검증: 컴포넌트 테스트 [사용자 결정]

### 5.4 심볼 변경
- EC-13: 심볼을 바꾸면 행 수와 입력값은 유지되고, 새 심볼의 `priceScale`·`qtyStep`·기초 코인으로 두 결과가 다시 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-14: 심볼을 바꾸면 수량 경고가 새 심볼의 `minOrderQty`·`qtyStep` 기준으로 다시 판정된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
