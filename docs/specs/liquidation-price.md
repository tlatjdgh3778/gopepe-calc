# 스펙: F-3 청산가

- 상태: 완료
- 최종 갱신: 2026-11-23

## 1. 목표
청산가 탭에서 사용자가 심볼·방향·레버리지·마진 모드(격리/교차)를 고르고 진입가·수량(교차면 계좌 잔고)과, 원하면 손절가를 넣으면 추정 청산가와 진입가 대비 거리(%)를 표시한다. 손절가가 청산가보다 불리하면 "손절 전에 청산됨"을, 포지션 가치가 유지증거금률 첫 단계 한도를 넘으면 한도 초과를 경고하고, 추정치라는 고지를 함께 띄운다. 청산가는 Bybit 공식 문서의 공식으로 계산하며, 계산 함수는 담보와 유지증거금률을 인자로 받아 F-6·F-10이 다시 쓸 수 있게 한다. [사용자 결정]

## 2. 비목표
- Bybit 화면 숫자와의 일치를 보장하지 않는다. mission의 "같은 입력이면 거래소 계산기와 같은 숫자" 원칙에서 F-3을 예외로 두고, 차이는 추정치 고지(DoD-28)로 알린다. [사용자 결정]
- 수수료(진입·종료·청산), 유지증거금 공제액, 마크가격, 펀딩, 추가 증거금을 반영하지 않는다. [사용자 결정]
- 유지증거금률 2단계 이상을 쓰지 않는다. 첫 단계 한도를 넘어도 첫 단계 `mmr`로 계산하고 경고만 띄운다. 전체 단계는 F-10에서 한다. [사용자 결정]
- 교차 모드에서 다른 포지션과 미실현 손익을 다루지 않는다. 계좌에 이 포지션 하나만 있다고 가정한다. [사용자 결정]
- 수량을 USDT 단위로 받지 않는다. 수량은 기초 코인 단위로만 받는다. [사용자 결정]
- 손절가에 도달했을 때의 손익 금액을 표시하지 않는다. 손절가는 청산가와 비교하는 데만 쓴다. [사용자 결정]
- `lib/pnl.ts`와 F-1 손익 계산기 화면(`components/pnl-calculator.tsx`)을 바꾸지 않는다. [사용자 결정]
- 공용 모듈(`lib/format.ts`, `lib/input.ts`, `lib/symbols.ts`, `lib/validation.ts`, `components/fields/*`, `components/calculator-layout.tsx`, `components/calculator-tabs.tsx`)을 바꾸지 않는다. F-1의 수량 경고 문구는 F-3 안에 같은 문구로 복제한다. [사용자 결정]

## 3. 완료의 정의

### 3.1 탭·화면 구성

- DoD-2: `app/page.tsx`에서는 F-3 자리 두 줄(import, 탭 항목)만 줄 끝에 `// F-3` 꼬리표를 남긴 등록 줄로 바뀌고, 인접 자리 사이의 `// ---` 구분 줄과 다른 자리 줄은 그대로다 — 검증: repo 테스트(`__tests__/repo/page-slots.test.ts`) [제안 후 승인]
- DoD-3: 청산가 계산기의 두 카드 제목과 region 접근 이름은 `청산가 입력`, `청산가 결과`다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- DoD-4: `청산가 입력` 카드에 심볼, 방향(`롱`/`숏`), 레버리지, 마진 모드, 진입가, 수량, 손절가 입력이 있다 — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-5: 마진 모드는 이름이 `마진 모드`인 그룹의 `격리`·`교차` 두 버튼으로 고르고, 처음에는 `격리`가 선택돼 있다 — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-6: `계좌 잔고` 입력란은 마진 모드가 `교차`일 때만 보인다 — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-7: 레버리지 입력란은 두 모드 모두에서 보이고, `교차`일 때만 그 아래에 `교차에서는 레버리지가 청산가에 영향을 주지 않습니다.`가 표시된다 — 검증: 컴포넌트 테스트 [사용자 결정] (문구는 [제안 후 승인])

### 3.2 청산가 계산
- DoD-8: `liquidationPrice`는 롱이면 `(entryPrice × qty − collateral) ÷ (qty × (1 − mmr))`의 반올림하지 않은 값을 돌려준다(예: 진입가 100000, 수량 0.1, 담보 1000, mmr 0.0033 → 90297.98334…) — 검증: 단위 테스트(손계산 리터럴) [사용자 결정]
- DoD-9: `liquidationPrice`는 숏이면 `(entryPrice × qty + collateral) ÷ (qty × (1 + mmr))`의 반올림하지 않은 값을 돌려준다(예: 진입가 100000, 수량 0.1, 담보 1000, mmr 0.0033 → 109638.19395…) — 검증: 단위 테스트(손계산 리터럴) [사용자 결정]
- DoD-10: `liquidationPrice({ side: "long", entryPrice: 40000, qty: 1, collateral: 3801.65, mmr: 0.005 })`은 Bybit 도움말(UTA 격리 모드 청산가) 예시의 36,380.25와 소수 2자리까지 같다(담보 3801.65 = 개시증거금 800 + 추가 증거금 3000 × (1 + 테이커 수수료 0.00055)) — 검증: 단위 테스트 [사용자 결정]
- DoD-11: `isolatedCollateral(entryPrice, qty, leverage)`는 `entryPrice × qty ÷ leverage`를 돌려준다 — 검증: 단위 테스트 [사용자 결정]
- DoD-12: 격리 모드의 추정 청산가는 담보를 `isolatedCollateral`(진입가 × 수량 ÷ 레버리지)로, `mmr`을 선택한 심볼의 `maintenanceTier.mmr`로 계산한다(예: BTCUSDT 롱, 레버리지 10, 진입가 100000, 수량 0.1 → `90,298.00`) — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-13: 교차 모드의 추정 청산가는 담보를 입력한 계좌 잔고로, `mmr`을 선택한 심볼의 `maintenanceTier.mmr`로 계산한다(예: BTCUSDT 롱, 진입가 100000, 수량 0.1, 계좌 잔고 2000 → `80,264.90`) — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-14: 교차 모드에서 레버리지 값을 바꿔도 추정 청산가와 거리는 바뀌지 않는다 — 검증: 컴포넌트 테스트 [사용자 결정]

### 3.3 표시
- DoD-15: `roundLiquidation(price, side, tickSize)`는 양수 `price`에 대해 롱이면 `roundToStep(price, tickSize, "up")`, 숏이면 `roundToStep(price, tickSize, "down")`과 같은 값을 돌려준다(예: 90297.983…, 롱, 0.1 → 90298.0 / 109638.193…, 숏, 0.1 → 109638.1) — 검증: 단위 테스트 [사용자 결정]
- DoD-16: `추정 청산가` 결과는 `roundLiquidation`으로 틱에 맞춘 값을 `formatPrice(값, priceScale)`로 표시한다 — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-17: `distancePercent(liq, entry)`는 `|liq − entry| ÷ entry × 100`을 돌려준다 — 검증: 단위 테스트 [사용자 결정]
- DoD-18: `formatDistance(v)`는 F-1 스펙 DoD-18과 같이 소수 10자리에서 오차를 정리한 뒤 부호 없이 소수 2자리로 0 방향 버림하고, 천 단위 구분을 넣고 `%`를 붙인다(예: 9.702 → `9.70%`, 1993.456 → `1,993.45%`). `null`이거나 유한하지 않으면 `—`(U+2014)를 돌려준다 — 검증: 단위 테스트 [사용자 결정]
- DoD-19: `청산가까지 거리` 결과는 DoD-16의 틱에 맞춘 청산가와 진입가로 계산한 `distancePercent`를 `formatDistance`로 표시한다(예: DoD-12 입력 → `9.70%`) — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-20: `추정 청산가`·`청산가까지 거리` 결과에는 손익 색이 붙지 않는다(`data-tone`이 `profit`·`loss`가 아니다) — 검증: 컴포넌트 테스트 [사용자 결정]

### 3.4 경고와 고지
- DoD-21: 레버리지가 심볼 최대치를 넘으면 F-7 스펙 DoD-9의 레버리지 경고가 레버리지 입력란 아래에 표시된다 — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-22: 수량이 최소 주문 수량보다 작거나 `qtyStep`의 배수가 아니면 F-7 스펙 DoD-11·DoD-12와 같은 문구가 수량 입력란 아래에 표시되고 입력란과 `aria-describedby`로 연결된다. 두 조건이 함께 성립하면 F-7 스펙 EC-1과 같이 최소 주문 수량 경고 하나만 표시한다 — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-23: `isStopBeforeLiquidation(side, stop, liq)`는 롱이면 `stop ≤ liq`, 숏이면 `stop ≥ liq`일 때 `true`를, 그 외와 `stop` 또는 `liq`가 `null`이면 `false`를 돌려준다 — 검증: 단위 테스트 [사용자 결정]
- DoD-24: 손절가가 DoD-16의 틱에 맞춘 청산가에 대해 DoD-23 조건을 만족하면 손절가 입력란 아래에 `⚠ 손절 전에 청산됩니다.`가 표시되고 입력란과 `aria-describedby`로 연결된다 — 검증: 컴포넌트 테스트 + E2E(Playwright) [사용자 결정]
- DoD-25: `exceedsFirstTier(entryPrice, qty, riskLimitValue)`는 `entryPrice × qty > riskLimitValue`이면 `true`, 같거나 작으면 `false`를 돌려준다 — 검증: 단위 테스트 [사용자 결정]
- DoD-26: 진입가 × 수량이 선택한 심볼의 `maintenanceTier.riskLimitValue`를 넘으면 `청산가 결과` 카드의 `추정 청산가` 바로 아래(`청산가까지 거리`보다 앞)에 `⚠ 포지션 가치가 유지증거금률 첫 단계 한도({riskLimitValue} USDT)를 넘습니다. 실제 청산가는 진입가에 더 가까울 수 있습니다.`가 표시된다. `{riskLimitValue}`는 천 단위 구분 정수다(예: `300,000`) — 검증: 컴포넌트 테스트 [사용자 결정] (문구는 [제안 후 승인])
- DoD-27: DoD-21·DoD-22·DoD-24·DoD-26·EC-7의 경고가 떠도 입력은 막히지 않고 추정 청산가와 거리는 계속 계산·표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- DoD-28: 청산가 계산기의 두 카드 아래에 `추정치입니다. 유지증거금률 첫 단계만 쓰고 수수료·유지증거금 공제액·마크가격·펀딩을 반영하지 않습니다. 교차는 계좌에 이 포지션 하나만 있다고 가정합니다. 거래소 표시값과 다를 수 있습니다.`가 입력과 관계없이 항상 표시된다 — 검증: 컴포넌트 테스트 [사용자 결정]

## 4. 인터페이스 계약
- `lib/liquidation.ts`(신규)는 다음을 export한다. 계산 함수는 반올림하지 않은 원값을 돌려주고, 입력이 비었거나(`null`) 0 이하이거나 결과가 유한하지 않으면 `null`을 돌려준다. [사용자 결정]
  ```ts
  export type MarginMode = "isolated" | "cross";
  export function liquidationPrice(input: {
    side: "long" | "short";
    entryPrice: number | null;
    qty: number | null;
    collateral: number | null; // 격리 = 개시증거금, 교차 = 계좌 잔고(USDT)
    mmr: number;               // 소수(0.0033 = 0.33%)
  }): number | null;
  export function isolatedCollateral(entryPrice: number | null, qty: number | null, leverage: number | null): number | null;
  export function roundLiquidation(price: number | null, side: "long" | "short", tickSize: number): number | null;
  export function distancePercent(liq: number | null, entry: number | null): number | null;
  export function isStopBeforeLiquidation(side: "long" | "short", stop: number | null, liq: number | null): boolean;
  export function exceedsFirstTier(entryPrice: number | null, qty: number | null, riskLimitValue: number): boolean;
  export function formatDistance(v: number | null): string;
  ```
- `liquidationPrice`는 롱의 원값이 0 이하여도 그 값을 돌려준다(`청산 없음` 판정은 호출자가 한다, EC-4). [제안 후 승인]
- `liquidationPrice`는 `mmr`이 0 이하이거나 1 이상이면 `null`을 돌려준다. [사용자 결정]
- `roundLiquidation`은 `price`가 `null`이거나 유한하지 않거나 0 이하이면 `null`을 돌려준다. [사용자 결정]
- `exceedsFirstTier`는 `entryPrice` 또는 `qty`가 `null`이거나 0 이하이면 `false`를 돌려준다. [사용자 결정]
- `components/liquidation-calculator.tsx`(신규)는 props 없는 `LiquidationCalculator`를 export한다. `app/page.tsx` 탭 항목은 `value: "liquidation"`, `label: "청산가"`다. [사용자 결정]
- 접근 이름: 그룹 `마진 모드`(버튼 `격리`·`교차`), 입력란 `진입가`·`수량`·`계좌 잔고`·`손절가`, 결과 행 `추정 청산가`·`청산가까지 거리`. 심볼·방향·레버리지는 공용 필드의 이름(`심볼`·`방향`·`레버리지`)을 그대로 쓴다. [사용자 결정]

## 5. 엣지 케이스와 실패 시나리오

### 5.1 입력 무효
- EC-1: 격리 모드에서 진입가·수량·레버리지 중 하나라도 비었거나 0 이하이면 `추정 청산가`·`청산가까지 거리`는 `—`다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-2: 교차 모드에서 진입가·수량·계좌 잔고 중 하나라도 비었거나 0 이하이면 `추정 청산가`·`청산가까지 거리`는 `—`다(레버리지는 비어 있어도 계산한다) — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-3: 손절가가 비었거나 0 이하이면 손절 경고를 판정하지 않는다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-14: 수량 원문이 비었거나 `.`이거나 0 이하이면 DoD-22의 수량 경고를 판정하지 않는다(F-7 스펙 EC-4와 같다) — 검증: 컴포넌트 테스트 [사용자 결정]

### 5.2 계산 결과 이상
- EC-4: 롱의 `liquidationPrice` 원값이 0 이하이면 `추정 청산가`에 `청산 없음`을 표시한다(예: 격리 레버리지 1, 또는 교차 잔고 ≥ 진입가 × 수량) — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-5: EC-4의 경우 `청산가까지 거리`는 `—`다 — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-6: `추정 청산가`가 `—` 또는 `청산 없음`이면 손절 경고를 표시하지 않는다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-7: 틱에 맞춘 청산가가 롱은 진입가 이상, 숏은 진입가 이하이면 값과 거리를 그대로 표시하고 `청산가 결과` 카드의 `추정 청산가` 바로 아래(`청산가까지 거리`보다 앞)에 `⚠ 진입 즉시 청산되는 포지션입니다.`를 표시한다 — 검증: 컴포넌트 테스트 [사용자 결정] (문구는 [제안 후 승인])
- EC-8: EC-7의 경고와 DoD-26의 한도 경고 조건이 함께 성립하면 두 경고를 즉시 청산 경고 → 한도 경고 순서로 모두 표시한다 — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-15: DoD-26의 한도 경고는 진입가·수량만으로 판정하므로 `추정 청산가`가 `—`·`청산 없음`이어도 조건이 성립하면 표시한다(예: 격리에서 레버리지가 비어 있음) — 검증: 컴포넌트 테스트 [사용자 결정]

### 5.3 손절가
- EC-9: 손절가가 이익 쪽(롱은 손절가 ≥ 진입가, 숏은 손절가 ≤ 진입가)이어도 따로 경고하지 않고 DoD-24의 판정만 한다 — 검증: 컴포넌트 테스트 [사용자 결정]

### 5.4 입력 전환
- EC-10: 마진 모드를 바꿔도 다른 입력값은 유지되고, `격리`로 돌아갔다가 다시 `교차`로 오면 이전 계좌 잔고 값이 그대로 있다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-11: 심볼을 바꾸면 입력값은 유지되고 결과·손절 경고·한도 경고는 새 심볼의 `tickSize`·`priceScale`·`maintenanceTier`로 다시 판정된다(예: 진입가 × 수량 = 100,000이면 SOLUSDT에서는 한도 경고, BTCUSDT에서는 없음) — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-12: DoD-26의 한도 경고는 교차 모드에서도 같은 조건으로 판정한다 — 검증: 컴포넌트 테스트 [제안 후 승인]
