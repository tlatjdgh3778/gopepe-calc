# 스펙: F-6 피라미딩 터미널

- 상태: 완료
- 최종 갱신: 2026-11-28

## 1. 목표
`/` 화면을 탭형 계산기 5개에서 거래 터미널형 피라미딩 화면 하나로 전면 교체한다(참고: `docs/product/references/pyramid-terminal-wireframe.html`의 "거래 터미널" 시안). 사용자가 심볼·방향·최초 진입가·초기 증거금·레버리지·수수료율과 추가 진입 단계(가격, 수익 재투입 %)를 넣으면 포지션 요약, 단계별 경로(차트·표), 익절, 손절 결과가 계산 버튼 없이 바로 표시된다. 손익·청산가·본전가는 진입·종료 수수료를 반영한 추정값이다. [사용자 결정]

## 2. 비목표
- 시나리오 저장·공유(저장 버튼, localStorage, JSON 내보내기)를 하지 않는다(F-12). [사용자 결정]
- 유지증거금률을 사용자가 입력하지 않고 다단계 MMR을 쓰지 않는다. 심볼의 첫 단계 MMR만 쓰고 한도 초과는 경고만 한다(다단계는 F-10). [사용자 결정]
- 최초·추가 수량을 `qtyStep`으로 내리지 않고 `minOrderQty`를 판정하지 않는다. 계산은 연속값이다. [사용자 결정]
- 격리/교차 선택, 유지증거금 공제액·마크가격·펀딩·슬리피지·다른 포지션을 반영하지 않는다. 시안의 단일 공유 담보 모델을 쓴다. [사용자 결정]
- 가격별 손익 곡선을 그리지 않는다(F-11). [사용자 결정]
- 기존 탭형 계산기 5개, `CalculatorTabs`·`CalculatorLayout`, 그에 걸린 컴포넌트 테스트·E2E·`page-slots` 원문 검사를 유지하지 않는다. `lib/`의 기존 모듈과 lib 테스트는 유지한다. [사용자 결정]
- 시스템 라이트 테마를 지원하지 않는다. 화면은 다크 고정이다. [사용자 결정]
- roadmap F-6 상태 갱신은 이 브랜치에서 하지 않는다. main 병합 후 별도 커밋으로 한다(F-2~F-5 관례). [사용자 결정]

## 3. 완료의 정의

### 3.1 계산 (`lib/pyramid.ts`)
- DoD-1: `simulatePyramid`의 진입 수수료는 각 진입(최초·포함된 추가 진입)의 진입가 × 수량 × feeRate 합이고, 총 수량은 최초 수량(margin × leverage ÷ entryPrice)과 포함된 추가 수량의 합, 평단은 Σ(진입가 × 수량) ÷ 총 수량의 반올림하지 않은 값이다 — 검증: 단위 테스트(기준 사례 P1·P2 손계산 리터럴, mock 없음) [사용자 결정]
- DoD-2: 추가 진입 단계의 가용 수익은 그 단계 가격에서 직전까지 포지션의 미실현 손익(수수료 미차감) − 앞 단계들이 이미 배정한 수익(0 미만이면 0)이고, 투입 증거금은 가용 수익 × 재투입% ÷ 100, 추가 수량은 투입 증거금 × 최초 레버리지 ÷ 단계 가격이다 — 검증: 단위 테스트 [사용자 결정]
- DoD-3: 추정 청산가 원값은 F-3 `liquidationPrice`에 collateral = margin − 누적 진입 수수료, mmr = 심볼 MMR + feeRate를 넣은 값이고, 재투입한 미실현 수익은 담보에 더하지 않는다. 단계 행의 청산가는 그 단계까지 반영한 값이다 — 검증: 단위 테스트 [사용자 결정]
- DoD-4: 총 자산은 margin + 마지막 포함 진입가 기준 미실현 손익 − 누적 진입 수수료, 최종 포지션 가치는 총 수량 × 마지막 포함 진입가, 실효 레버리지는 최종 포지션 가치 ÷ margin이다 — 검증: 단위 테스트 [사용자 결정]
- DoD-5: `netPnl(exitPrice)`는 방향 × (exitPrice × 총 수량 − Σ진입가×수량) − 누적 진입 수수료 − exitPrice × 총 수량 × feeRate다 — 검증: 단위 테스트 [사용자 결정]
- DoD-6: `baselinePnl(exitPrice)`는 최초 수량만으로 진입해 같은 가격에 종료했을 때의 순손익(최초 진입 수수료와 그 수량의 종료 수수료 차감)이다 — 검증: 단위 테스트 [사용자 결정]
- DoD-7: `priceForRoe(roe)`는 `netPnl(p) = roe ÷ 100 × margin`을 p에 대해 푼 값이고, 본전가는 `priceForRoe(0)`이다 — 검증: 단위 테스트 [사용자 결정]

### 3.3 결과 표시
- DoD-17: 포지션 요약에 평균 진입가(보조: `최초 진입 대비 {±x.xx%} 이동`), 추정 청산가, 실효 레버리지(보조: `최초 {N}× → {x.xx}× 노출`), 총 포지션 수량, 최종 진입 시 포지션 가치, 실제 투입 원금, 미실현 수익 포함 총 자산, 수수료 포함 본전가, 누적 진입 수수료가 표시된다 — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-18: 표시 형식은 가격 `formatPrice(v, priceScale)`, 수량 `formatCoinQty(v, qtyStep)` + 공백 + 기초 코인, USDT 금액 `formatUsdt`(손익은 부호 표시·손익 색), 평단 이동·ROE·원금 대비 % `formatPercent`, 거리·역행 % `formatDistance`, 실효 레버리지 소수 2자리 버림(천 단위 구분) + `×`, 손익비 `1 : {소수 2자리 버림}`, 배수 `{소수 2자리 버림(천 단위 구분)}배`다 — 검증: 컴포넌트 테스트(P1·P2 표시값) [제안 후 승인]
- DoD-19: 추정 청산가(요약·표·손절 거리·손절 전 청산 판정)는 `roundLiquidation`(롱 틱 올림, 숏 틱 내림)으로 틱에 맞춘 값이고, 평단·본전가는 틱에 맞추지 않는다 — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-20: 경로 표의 열은 `진입 단계 | 진입가 | 누적 평단 | 청산가 | 재투입 | 시점 수익 | 투입 증거금 | 추가 수량`이고, 첫 행은 최초 진입(재투입·시점 수익 `—`, 투입 증거금 = 초기 증거금), 이후 행은 단계마다 한 행이다. 단계 행의 진입 단계 칸은 `N차 추가 진입`, 재투입 칸은 끝자리 0 없는 숫자 + `%`(예: `100%`, `12.5%`)다. 제외 행 표시는 EC-12·EC-16과 일치한다 — 검증: 컴포넌트 테스트 [사용자 결정] (행 이름·재투입 형식은 [제안 후 승인])
- DoD-21: 경로 차트는 Recharts(shadcn chart)로 진입가·누적 평단·청산가 선 3개를 최초 진입과 포함된 단계 순서대로 그리고(제외된 단계는 점이 없다, 청산가는 DoD-19의 틱 값) 범례와 툴팁을 둔다 — 검증: E2E(실제 브라우저에서 SVG 선 3개 렌더). 컴포넌트 테스트의 Recharts mock 경계는 테스트 설계 단계에서 확정 [사용자 결정]
- DoD-22: 목표 수익률(%)을 입력하면 익절가가 `priceForRoe`를 틱에 맞춘 값(롱 올림, 숏 내림)으로 바뀐다(예: P1에서 50 → 2158.21). 자동으로 채우는 가격 문자열은 천 단위 구분·지수 표기·끝자리 0 없이 쓴다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- DoD-23: 목표 수익률 외의 입력(익절가 포함)이 바뀌면 목표 수익률 입력란이 `netPnl(익절가) ÷ margin × 100`의 소수 2자리 버림 값(천 단위 구분 없음)으로 다시 채워지고 익절가는 그대로다(처음 연 화면은 240.40) — 검증: 컴포넌트 테스트 [제안 후 승인]
- DoD-24: 익절 패널에 예상 순수익(`netPnl(익절가)`)과 ROE, 비교 막대 `추가 진입 없이`(`baselinePnl`)·`피라미딩 적용`, `추가 진입 효과 {차이}`가 표시된다 — 검증: 컴포넌트 테스트 [사용자 결정]
- DoD-25: 손절 패널에 손절 시 예상 손익(`netPnl(손절가)`)과 원금 대비 %, 손익비, 최종 진입가 → 추정 청산가 거리(|마지막 진입가 − 청산가| ÷ 마지막 진입가 × 100)와 손절가 위치 마커(장식, `aria-hidden`, 위치는 방향 × (마지막 진입가 − 손절가) ÷ |마지막 진입가 − 틱 청산가| × 100을 0~100으로 자른 %)가 있다 — 검증: 컴포넌트 테스트(마커는 손절 region 안 `data-slot="stop-marker"` 요소, inline `style.left`를 ±0.01%p로 비교) [사용자 결정] (마커 위치·접근 처리는 [제안 후 승인])
- DoD-26: 포지션 요약 아래 리스크 문구는 `마지막 진입가에서 {x.xx%} 역행하면 수수료 포함 전체 수익이 사라집니다.`(x = |마지막 진입가 − 본전가| ÷ 마지막 진입가 × 100)다. 표시 조건은 §5.3과 일치한다 — 검증: 컴포넌트 테스트 [사용자 결정]

## 4. 인터페이스 계약
- `lib/pyramid.ts` 입력: `PyramidInput = { side: "long" | "short"; entryPrice: number | null; margin: number | null; leverage: number; feeRate: number; mmr: number; steps: readonly { price: number | null; reinvestPercent: number | null }[] }`. `feeRate`·`mmr`은 소수(0.055% → 0.00055), `reinvestPercent`는 % 숫자(허용 범위 1 이상 100 이하)다. [제안 후 승인]
- `simulatePyramid(input): PyramidResult | null` — 반올림하지 않은 원값. entryPrice·margin이 0 이하이거나 null, leverage가 1 미만, feeRate가 0 미만이거나 0.01 이상이면 null이다. [제안 후 승인]
- `PyramidResult`: `totalQty`, `avgPrice`, `entryFees`, `lastPrice`, `liquidationPrice`(원값, 0 이하일 수 있음. collateral = margin − 누적 진입 수수료가 0 이하이면 null. 행의 `liquidationPrice`도 같다), `equity`, `finalNotional`, `effectiveLeverage`, `breakEvenPrice`, `rows: PyramidRow[]`(최초 진입 행 + 단계별 행). [제안 후 승인]
- `PyramidRow`: `price`, `reinvestPercent`(최초 행 null), `pnlAtStep`(최초 행 null), `marginUsed`, `addedQty`, `avgPrice`, `liquidationPrice`, `excluded: "invalidInput" | "notProfitDirection" | "noProfit" | "empty" | null`. 제외된 행의 `marginUsed`·`addedQty`는 0이고, `invalidInput`·`empty` 행의 `pnlAtStep`은 null이다. [제안 후 승인]
- `netPnl(input, result, exitPrice)`, `baselinePnl(input, exitPrice)`, `priceForRoe(input, result, roePercent)`: 모두 `number | null`. 인자가 무효(0 이하 가격, null)이거나 결과가 유한하지 않으면 null이다. [제안 후 승인]
- 문자열→숫자 변환, 틱 반올림, 표시 형식은 컴포넌트가 맡는다. 손익비·거리 %는 컴포넌트가 이 결과와 기존 `distancePercent`·`isStopBeforeLiquidation`·`roundLiquidation`으로 만든다. [제안 후 승인]
- 함수·필드 이름과 파일 위치는 계획 단계에서 조정할 수 있다. 고정하는 계약은 입출력의 의미·단위·null 규칙, 접근 이름(DoD-32·DoD-34), region 이름이다. [제안 후 승인]
- URL은 `/`만 쓴다. 새 라우트·API는 없다. [제안 후 승인]
- 추가 의존성: `recharts`(shadcn `chart`를 통해), `pretendard`. 추가하는 shadcn 컴포넌트: `button`, `slider`, `dialog`, `chart`. [사용자 결정]

### 5.1 기본 입력 비정상·결과 경계

- EC-3: 거래 수수료율이 빈칸이면 결과가 모두 `—`다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-4: 거래 수수료율이 1 이상이면 결과가 모두 `—`이고 `⚠ 수수료율은 1% 미만이어야 합니다.`가 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-5: 거래 수수료율 0은 허용되고 수수료 없이 계산된다 — 검증: 단위 테스트 [제안 후 승인]
- EC-6: 레버리지 입력란이 빈칸인 동안 결과가 모두 `—`다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-7: 레버리지 입력란에 0이나 `maxLeverage` 초과 값을 넣고 포커스를 빼면 값이 1 또는 `maxLeverage`로 바뀐다 — 검증: 컴포넌트 테스트 [제안 후 승인]

### 5.2 추가 진입 단계
- EC-12: 단계의 한 칸만 비었거나, 가격이 0이거나, 재투입이 1 미만 또는 100 초과이면 그 단계는 `invalidInput`으로 제외되고 단계 카드 아래 `⚠ N차 추가 진입 제외: 가격과 재투입 비율(1~100%)을 확인해 주세요.`, 표의 그 행에 `제외`가 표시된다 — 검증: 단위 테스트 + 컴포넌트 테스트 [제안 후 승인]
- EC-13: 단계 가격이 제외되지 않은 마지막 진입가보다 수익 방향이 아니면(롱 이하, 숏 이상) `notProfitDirection`으로 제외되고 `⚠ N차 추가 진입 제외: 수익 방향으로 진행하는 가격을 입력해 주세요.`가 표시된다 — 검증: 단위 테스트 + 컴포넌트 테스트 [사용자 결정]
- EC-14: 가용 수익이 0 이하이면 `noProfit`으로 제외되고 `⚠ N차 추가 진입 제외: 재투입할 수 있는 수익이 없습니다.`가 표시된다. EC-13을 통과한 단계는 정확한 산술에서 가용 수익이 항상 양수이므로 이 판정은 부동소수점 오차 대비 방어 분기다 — 검증: 테스트 제외(정확한 산술로 도달하는 입력이 없다. 7단계 코드 대조로 분기 존재만 확인) [사용자 결정] (방어 분기·테스트 제외는 [사용자 결정] 2026-11-26)
- EC-15: 제외된 단계는 뒤 단계의 가용 수익·방향 판정·수량에 영향을 주지 않는다 — 검증: 단위 테스트 [제안 후 승인]
- EC-16: 가격과 재투입이 모두 빈 단계는 경고 없이 `empty`로 제외되고 표의 그 행에 `제외`가 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-17: 재투입은 소수(예: 12.5)를 허용한다 — 검증: 단위 테스트 [제안 후 승인]
- EC-18: 단계가 8개이면 `추가 진입 단계` 버튼이 비활성화되고 그 아래 `최대 8단계까지 추가할 수 있습니다.`가 표시된다 — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-19: 단계를 모두 삭제하면 포커스가 `추가 진입 단계` 버튼으로 가고 결과는 최초 진입만으로 계산된다 — 검증: 컴포넌트 테스트 [제안 후 승인]

### 5.3 익절·손절
- EC-20: 목표 수익률로 역산한 가격이 0 이하이거나 없으면 익절가는 바뀌지 않고 `⚠ 이 수익률에 해당하는 가격이 없습니다.`가 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인] (판정은 입력란의 현재 값 기준이다. 한 글자씩 입력하는 중의 유효한 중간값은 DoD-22대로 익절가에 반영되고, 마지막 값이 무효면 익절가는 마지막 유효값에 머문다 — [사용자 결정] 2026-11-27)
- EC-21: 익절가가 빈칸이면 익절 패널 결과와 손익비가 `—`이고, 0이면 같은 처리에 `⚠ 0보다 커야 합니다.`가 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-22: 손절가가 빈칸이면 손절 손익·원금 대비·손익비가 `—`이고, 0이면 같은 처리에 `⚠ 0보다 커야 합니다.`가 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-23: 익절가가 마지막 포함 진입가보다 수익 방향의 반대쪽이면 `⚠ 익절가가 마지막 추가 진입가보다 앞에 있습니다. 경로를 확인해 주세요.`가 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-24: 손절가가 마지막 포함 진입가의 수익 방향에 있으면 `⚠ 손절가가 최종 진입가의 수익 방향에 있습니다.`가 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-25: 손절가가 틱 청산가 너머이거나 같으면(`isStopBeforeLiquidation`) `⚠ 손절 전에 청산될 수 있습니다. 손절가를 확인하세요.`가 표시된다 — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-26: 손절 손익이 0 이상이거나 익절 순수익이 0 이하이면 손익비는 `—`다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-27: 청산 없음(EC-8)이면 청산가까지 거리는 `—`이고 EC-25 경고는 표시되지 않는다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-28: 추가 진입 효과의 배수(`· x.xx배`)는 순수익과 `추가 진입 없이` 값이 모두 양수일 때만 붙는다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-29: 리스크 문구(DoD-26)는 포함된 추가 진입이 1개 이상이고 마지막 포함 진입가가 본전가보다 수익 쪽(롱 위, 숏 아래)일 때만 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]

### 5.4 무효 상태·입력 중 상태
- EC-30: 기본 입력이 무효라 `simulatePyramid`가 null이면 경로 표에 본문 행이 없고, 차트를 그리지 않으며, 비교 막대와 보조 문구(평단 이동·레버리지 변화)를 표시하지 않고, 목표 수익률 입력란은 빈칸이다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-31: `simulatePyramid`가 null일 때 단계를 추가하면 새 단계 가격은 최초 진입가가 유효한 양수이면 그 값 기준(DoD-27 규칙), 아니면 빈칸이고 재투입은 100이다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-32: 목표 수익률이 빈칸이거나 `-`만 입력된 상태이면 경고 없이 익절가가 그대로다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-33: 레버리지 입력란에 범위 밖 값을 입력하는 동안(포커스 이탈 전) 계산과 슬라이더는 1~`maxLeverage`로 맞춘 값을 쓰고, 빈칸에서 포커스를 빼면 빈칸이 그대로다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-34: 누적 진입 수수료가 증거금 이상(담보 0 이하)이면 추정 청산가는 `—`, 포지션 요약에 `⚠ 진입 즉시 청산되는 포지션입니다.`가 표시되고, 청산가까지 거리는 `—`, EC-25 경고는 표시되지 않는다 — 검증: 단위 테스트(null) + 컴포넌트 테스트 [사용자 결정]
- EC-35: 경로 표의 제외 행은 진입 단계 칸에 `N차 추가 진입`과 `제외`, 진입가·재투입 칸에 입력값(숫자로 읽히면 포함 행과 같은 형식 — 진입가 `formatPrice`, 재투입 끝자리 0 없는 숫자 + `%`, 무효 값도 같은 형식(예: `0.00`, `101%`) — 빈칸·`.`이면 `—`), 시점 수익·투입 증거금·추가 수량·누적 평단·청산가 칸에 `—`를 표시한다 — 검증: 컴포넌트 테스트 [제안 후 승인]
