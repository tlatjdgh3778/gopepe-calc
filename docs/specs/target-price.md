# 스펙: F-2 목표가

- 상태: 완료
- 최종 갱신: 2026-11-23

## 1. 목표
사용자가 `/` 화면의 "목표가" 탭에서 심볼(BTCUSDT·ETHUSDT·SOLUSDT)·방향(롱·숏)·레버리지·진입가·목표 ROE(%)를 넣으면, 표시된 가격에서 종료했을 때 ROE가 목표 이상이 되는 목표가(심볼 틱 단위. "목표 이상"은 공용 `roundToStep`의 부동소수점 허용치(F-7 `docs/specs/input-validation.md` DoD-3) 안에서 성립하며, 원값이 틱 배수에 그 허용치만큼 가까우면 그 배수로 맞춰져 실제 ROE가 목표보다 극미하게 작을 수 있다 [사용자 결정])와 진입가 대비 가격 변동률이 계산 버튼 없이 바로 표시된다. ROE는 F-1(`docs/specs/pnl-calculation.md`) DoD-4와 같은 정의이고, 음수 목표 ROE(손실 목표)도 받는다. [사용자 결정]

## 2. 비목표
- 목표 수익률을 가격 변동률로 입력받지 않는다. ROE 기준만 두고 기준 전환 토글을 만들지 않는다. [사용자 결정]
- 수량 입력과 예상 손익(USDT) 결과를 두지 않는다. 손익 계산은 F-1이 맡는다. [사용자 결정]
- 공용 모듈(`lib/input.ts`, `lib/format.ts`, `lib/symbols.ts`, `lib/pnl.ts`, `components/fields/`의 기존 파일, `components/calculator-layout.tsx`, `components/calculator-tabs.tsx`)과 `CLAUDE.md`의 공용 모듈 목록을 수정하지 않는다. [사용자 결정]
- 정확한 청산가 계산(F-3)과 수수료 반영(F-8)을 하지 않는다. [제안 후 승인]
- 계산기 사이에 입력을 공유하지 않는다. 손익 탭과 목표가 탭은 각자 상태를 갖는다. [제안 후 승인]
- 새 Bybit 기준 사례를 수집하지 않는다. 기준 사례는 F-1 C1~C6의 역산과 손계산으로 만든다. [사용자 결정]
- 중간 계산이나 결과가 부동소수점 범위를 넘는 극단 입력(레버리지·진입가·목표 ROE가 대략 1e300 이상, 진입가 ÷ 틱이 오버플로하는 경우 등)에서 목표가·가격 변동률의 정확성(§1 "목표 이상", EC-4 포함)은 보장하지 않는다. 이런 입력에서 보장하는 것은 §5 머리의 공통 불변식(`NaN`·`Infinity`·오류 없음)뿐이다. [사용자 결정]

## 3. 완료의 정의
- DoD-1: `calculateTargetPrice`의 롱 원값 목표가는 진입가 × (1 + 목표 ROE ÷ (100 × 레버리지))다 — 검증: 단위 테스트 [사용자 결정]
- DoD-2: 숏 원값 목표가는 진입가 × (1 − 목표 ROE ÷ (100 × 레버리지))다 — 검증: 단위 테스트 [사용자 결정]
- DoD-3: 롱의 `targetPrice`는 원값 목표가를 `roundToStep(원값, tickSize, "up")`으로 맞춘 값이다(목표 ROE의 부호와 무관) — 검증: 단위 테스트 [사용자 결정]
- DoD-4: 숏의 `targetPrice`는 원값 목표가를 `roundToStep(원값, tickSize, "down")`으로 맞춘 값이다(목표 ROE의 부호와 무관) — 검증: 단위 테스트 [사용자 결정]
- DoD-5: `priceChangePercent`는 `targetPrice` 기준 (`targetPrice` − 진입가) ÷ 진입가 × 100의 반올림하지 않은 값이고, 가격이 오르면 양수, 내리면 음수다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-6: 아래 기준 사례 T1~T6 각각에서 `targetPrice`가 표의 목표가와 같다 — 검증: 단위 테스트(손계산 리터럴, mock 없음) [사용자 결정]
- DoD-7: 기준 사례 T1~T6 각각에서 `targetPrice`를 종료가로 F-1 `calculatePnl`에 넣은 `roe`는 목표 ROE 이상이다(수량은 임의의 양수) — 검증: 단위 테스트(mock 없음) [사용자 결정]
- DoD-8: 목표가 탭의 초깃값은 심볼 BTCUSDT, 방향 롱, 레버리지 10이고, 진입가·목표 ROE는 비어 있으며 두 결과는 `—`다 — 검증: 컴포넌트 테스트(RTL + user-event, jsdom) [제안 후 승인]
- DoD-9: 목표가 탭의 입력 카드에 심볼 정보 기준일 문구(`SymbolSelect`의 문구)가 표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- DoD-10: 진입가·목표 ROE를 입력하면 계산 버튼 없이 목표가가 `formatPrice(targetPrice, priceScale)` 형식(예: T1 → `67,250.30`)으로 표시된다 — 검증: 컴포넌트 테스트 [사용자 결정]

## 4. 인터페이스 계약
- `lib/target-price.ts`: `calculateTargetPrice(input: { side: "long" | "short"; leverage: number; entryPrice: number | null; targetRoe: number | null; tickSize: number }): { targetPrice: number | null; priceChangePercent: number | null }`. `targetRoe`는 % 단위이고 음수와 0을 허용한다. `targetPrice`는 틱에 맞춘 값이다. 레버리지·진입가가 없거나 0 이하이거나, `targetRoe`가 없거나, 결과가 유한하지 않거나, `targetPrice`가 0 이하이면 두 필드 모두 `null`이다. [제안 후 승인]
- `components/target-price-calculator.tsx`: `TargetPriceCalculator`(props 없음). [제안 후 승인]
- `components/fields/signed-decimal-field.tsx`(새 파일): 맨 앞 `-` 하나를 허용하는 숫자 입력란. 공용 `filtered`·`toNumber`를 재사용한다. [사용자 결정] 이 입력란에는 `inputMode`를 두지 않는다(모바일 숫자 키패드에 `-`가 없는 경우를 피한다). [사용자 결정]
- `app/page.tsx` 탭 항목: `value` `"target"`, `label` `"목표가"`, `content`는 `TargetPriceCalculator` 요소이고 줄 끝에 꼬리표 `// F-2`를 둔다. [제안 후 승인]
- 함수 이름·파일 위치는 구현 단계에서 바꿀 수 있다. 고정하는 계약은 입출력의 의미와 `null` 규칙, 입력·결과 라벨, 탭 항목의 `label`이다. [제안 후 승인]
- URL은 `/`만 쓴다. 새 라우트·API는 없다. [제안 후 승인]

## 5. 엣지 케이스와 실패 시나리오
화면에는 어떤 입력에서도 `NaN`·`Infinity`·오류가 나타나지 않는다. [제안 후 승인]

### 5.1 비정상 입력
- EC-1: 목표 ROE 입력란은 맨 앞의 `-` 하나, 숫자, 소수점 하나만 받는다. 다른 문자·두 번째 `-`·맨 앞이 아닌 `-`·두 번째 소수점이 하나라도 섞인 변경(붙여넣기 포함)은 통째로 무시되고 직전 값이 유지된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-2: 목표 ROE가 비어 있거나 `-`·`.`·`-.`이면 목표가·가격 변동률은 `—`다 — 검증: 단위 테스트(`null` 반환) + 컴포넌트 테스트 [제안 후 승인]
- EC-3: 진입가나 레버리지가 비어 있거나 `.`이거나 0이면 목표가·가격 변동률은 `—`다 — 검증: 단위 테스트(`null` 반환) + 컴포넌트 테스트 [제안 후 승인]
- EC-4: 진입가가 심볼 틱의 배수이고 목표 ROE가 0이면 목표가는 진입가와 같고 가격 변동률은 부호 없는 `0.00%`다. 진입가가 틱 배수가 아니면 DoD-3·DoD-4의 반올림을 그대로 따른다 — 검증: 단위 테스트 + 컴포넌트 테스트 [제안 후 승인] (틱 배수 한정은 [사용자 결정])
- EC-5: 레버리지가 심볼 최대치를 넘으면 `LeverageField`의 최대 레버리지 경고가 표시되고 목표가·가격 변동률은 계속 계산·표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]

### 5.2 결과 경계
- EC-6: 틱에 맞춘 목표가가 0 이하이면(예: 숏 10x 목표 ROE 1000, 롱 10x 목표 ROE -1000) 목표가·가격 변동률은 `—`다 — 검증: 단위 테스트(`null` 반환) + 컴포넌트 테스트 [사용자 결정]
- EC-7: EC-6의 경우 목표 ROE 입력란 아래에 `⚠ 이 ROE에 해당하는 가격이 없습니다.`가 표시되고 입력란과 `aria-describedby`로 연결된다 — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-8: 목표 ROE가 −100 이하이면 목표 ROE 입력란 아래에 `⚠ 증거금 이상 손실 — 이 가격 전에 청산됩니다.`가 표시되고 입력란과 `aria-describedby`로 연결된다. 목표가 표시 여부는 EC-6을 따른다(예: T3은 목표가가 표시된다) — 검증: 컴포넌트 테스트 [사용자 결정]
- EC-9: EC-6에 해당하면서 목표 ROE가 −100 이하이면(예: 롱 10x 목표 ROE -1000) EC-7의 경고 하나만 표시하고 EC-8의 경고는 표시하지 않는다 — 검증: 컴포넌트 테스트 [사용자 결정]

### 5.3 입력 상태 전환
- EC-10: 심볼을 바꾸면 입력값은 유지되고 새 심볼의 `tickSize`·`priceScale`로 목표가·가격 변동률이 다시 계산·표시된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-11: 방향을 바꾸면 입력값은 유지되고 바뀐 방향의 공식(DoD-1·DoD-2)과 반올림 방향(DoD-3·DoD-4)으로 다시 계산된다 — 검증: 컴포넌트 테스트 [제안 후 승인]
- EC-12: 입력을 지워 계산할 수 없게 되면 두 결과가 `—`로 돌아가고 EC-7·EC-8의 경고도 사라진다 — 검증: 컴포넌트 테스트 [제안 후 승인]
